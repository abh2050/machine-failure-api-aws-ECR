# Machine Failure API — visual documentation

Open [index.html](index.html) in a browser for the engineering case study. It works directly from disk; an internet connection is optional for Google Fonts (system fonts are the fallback). The photograph and diagram assets are local.

## Diagrams

- [System architecture](diagrams/system-architecture.html): API Gateway, Lambda, ECR, and CloudWatch.
- [Training pipeline](diagrams/training-pipeline.html): feature transform, dataset partitions, estimator, threshold selection, and export.
- [Inference path](diagrams/inference-path.html): input validation, feature construction, ONNX execution, and response.

Each standalone Archify viewer includes light/dark themes, search, focus, tracing, zoom, and export. Editable JSON specifications are in `specs/`. The three views use Archify's architecture schema; the pipeline and inference views are component-flow representations.

## Sources and interpretation

Implementation: `app.py`, `features.py`, `train.py`, `Dockerfile`, and `deploy.sh`. Metrics: `model/metadata.json` and the repository README's Gate 6 record. Documentation does not query AWS or call the inference endpoint. Reported latency and cost are historical observations, not fresh measurements or service guarantees.

The training view compresses evaluation/export into one artifact node: threshold tuning uses validation scores, and test scores feed both final metrics and the ONNX parity check. The initialization guard is described separately from per-request execution. The system view shows EMF extraction from logs, not direct metric API writes.

[UCI's dataset page](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset) identifies AI4I 2020 as synthetic. Model results are benchmark results, not validation on a real factory fleet.

## Regeneration

With the Archify skill installed, run from the repository root (replace `/path/to/archify` with the skill directory):

```sh
node /path/to/archify/bin/archify.mjs validate architecture docs/specs/system-architecture.json --quality showcase --json
node /path/to/archify/bin/archify.mjs deliver architecture docs/specs/system-architecture.json docs/diagrams/system-architecture.html --quality showcase --json
node /path/to/archify/bin/archify.mjs visual-check docs/diagrams/system-architecture.html --json
```

Repeat for `training-pipeline` and `inference-path`. Refresh the index's SVG preview after changing the system diagram. Its SVG and stylesheet are extracted from the delivered HTML; it is a preview, not a separately authored topology.

Artifact hashes, showcase validation, and browser receipts are in `evidence/`. Browser screenshots and contact sheets generated by Archify sit alongside the delivered diagrams. See [review results](evidence/REVIEW.md).
